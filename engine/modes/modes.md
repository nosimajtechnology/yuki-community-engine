# Engine modes

Select one primary mode. A mode controls deliverables and approval gates, not Yuki's canon.

## CHARACTER

Purpose: clean canonical representation, turnaround-derived portrait, pose study, expression sheet, or approved alternate outfit study.

Deliver:

- reference declaration;
- immutable-trait checklist;
- pose/expression/composition;
- clean background and lighting plan;
- generation brief and mutation exclusions.

Default to the signature outfit. Do not add story lore.

## STILL

Purpose: one finished composition with a clear visual idea.

Deliver a single frame with subject hierarchy, environment, camera, action/pose, period anchors, canon lock, and negative constraints. Treat any story implied by the image as interpretation.

## SCENE

Purpose: one event or environment centered on Yuki; may return a genesis frame first when the user intends to animate it.

Define: what is already happening, where Yuki is, one primary action, environmental reaction, spatial layout, and the exact state at the end. Avoid turning a scene into an unrequested multi-shot sequence.

## CLASSIC CINEMATIC

Purpose: Nosimaj-style short cinematic with controlled approvals.

Flow:

1. Refine the premise into a visual hook and one action spine.
2. Produce a genesis-frame brief. Start mid-action when an immediate hook is requested.
3. Wait for explicit approval.
4. Produce five to seven shots. Every shot must advance the same event; vary perspective and shot function, not identity or geography.
5. Wait for explicit approval.
6. Produce a model-neutral animation brief, then the requested adapter.

Default: no dialogue or on-screen copy unless it is essential. Never generate a provider prompt before storyboard approval unless the user explicitly waives the gate.

## MEME

Purpose: fast, culturally legible, remix-friendly concept.

Deliver:

- premise in one line;
- recognition mechanism (situation, format, or cultural reference);
- one-frame or short-loop composition;
- optional caption/copy separated from the image prompt;
- canon lock and safe remix boundary.

Prefer simple visual logic. Do not use invented lore as the joke unless labeled fictional.

## COMMERCIAL

Purpose: fictional advertisement, product spot, service ident, PSA, infomercial, or branded Y2Kverse media.

Define the fictional brand/product, first-second hook, proof/action, payoff, and optional logo end card. Keep real Y2K/Yuki attribution distinct from the fictional company. Do not make real financial, product, or token claims.

Use the cinematic approval flow when multi-shot. Dialogue and narration are optional, never assumed.

## EPISODE

Purpose: longer continuous narrative built through progressive approved storyboards.

Default structure:

1. **Storyboard 1 — Hook + Setup:** begin with the premise already active or visibly imminent; establish character, geography, rules, and the first problem.
2. **Storyboard 2 — Escalation / Development:** continue the exact final state, complicate the problem, and deepen the action.
3. **Storyboard 3 — Major Development / Turn:** introduce the decisive reveal, reversal, choice, or consequence through visible action.
4. **Storyboard 4 — Payoff / Resolution:** resolve the established spine and leave a deliberate final condition.
5. **Storyboard 5 — Optional:** requires structural justification; use only for a true aftermath, second-stage payoff, or unavoidable structural beat that would otherwise overload Board 4. State the justification before creating it.

Each board contains five to seven shots unless the user requests another count. Produce one board at a time and wait for approval. Read the previous approved board and update the continuity ledger before the next board. The first shot of Board N must visibly inherit the last shot of Board N-1.
